## Usage guidelines

- **An AI SDK message fits as it is** — `UIMessage` satisfies `ChatMessage` structurally, so the messages `useChat` returns need no adapter to reach code typed with `ChatMessage`. The reverse doesn't hold, because `role` here is any string.
- **Narrow with the guards** — `UnknownPart` keeps `MessagePart` open, so `part.type === "text"` doesn't narrow a part and `isTextPart(part)` does.
- **Unknown parts pass through** — a part no type here describes, such as `step-start`, `dynamic-tool` or `source-document`, still fits as `UnknownPart`. Nothing drops it, so your renderer decides whether to draw it.
- **Expect more tool states** — the AI SDK's tool parts have three states `ToolPartState` doesn't list: `approval-requested`, `approval-responded` and `output-denied`. `isToolPart` lets those parts through, so give your renderer a fallback.
- **Count `"submitted"` as generating** — `ChatStatus` is `"submitted"` from the send until the reply starts. Treat it like `"streaming"`, otherwise the stop button and any pending indicator wait for the first chunk.
- **Imports anywhere** — the module holds types and five plain functions with no `"use client"` directive, so a server can import it too.
- **Get started** — see [Quick start](/quick-start) to add the package.

## Anatomy

```ts
type ChatMessage = {
  id: string;
  role: string;
  metadata?: unknown;
  parts: MessagePart[];
};
```

A component typed with `ChatMessage` takes the messages `useChat` returns as they are, and `isTextPart` picks out their text.

```tsx
"use client";

import { useChat } from "@ai-sdk/react";
import { Message } from "@intentface/ui/message";
import { type ChatMessage, isTextPart } from "@intentface/ui/types";

const Row = ({ message }: { message: ChatMessage }) => (
  <Message.Root role={message.role}>
    {message.parts.filter(isTextPart).map((part, index) => (
      <Message.Text key={index}>{part.text}</Message.Text>
    ))}
  </Message.Root>
);

export const Messages = () => {
  const { messages } = useChat();
  return messages.map((message) => <Row key={message.id} message={message} />);
};
```

## API reference

Every type here is structural, so anything with the same shape fits, an AI SDK message included.

### ChatMessage

A chat message. An AI SDK `UIMessage` satisfies it structurally, so no adapter is needed. `Metadata` types `metadata`, and `Part` types each part.

```ts
type ChatMessage<Metadata = unknown, Part extends UnknownPart = MessagePart>
```

### MessagePart

Every part a message carries. `UnknownPart` keeps the union open, so a check on `part.type` can't narrow it. Use the [part guards](#part-guards) instead.

```ts
type MessagePart =
  | TextPart
  | ReasoningPart
  | FilePart
  | SourceUrlPart
  | ToolPart
  | DataPart
  | UnknownPart;
```

### ToolPart

A tool call. `type` is `tool-` followed by the tool's name, and the type parameters type `input` and `output`. `isToolPart` narrows to `ToolPart<unknown, unknown>`, so check `input` and `output` before you read a field.

```ts
type ToolPart<Input = unknown, Output = unknown>
```

### Part guards

Each guard takes any part and narrows it to one type.

```ts
isTextPart(part: UnknownPart): part is TextPart
isReasoningPart(part: UnknownPart): part is ReasoningPart
isFilePart(part: UnknownPart): part is FilePart
isSourceUrlPart(part: UnknownPart): part is SourceUrlPart
isToolPart(part: UnknownPart): part is ToolPart
```

`isTextPart`, `isReasoningPart`, `isFilePart` and `isSourceUrlPart` narrow a part when its `type` is `"text"`, `"reasoning"`, `"file"` or `"source-url"`. `isToolPart` narrows a part to `ToolPart` when its `type` starts with `tool-` and it has `state` and `toolCallId`. A `dynamic-tool` part doesn't match.
